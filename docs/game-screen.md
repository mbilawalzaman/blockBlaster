# Milestone 2: playable screen

Pocket Mosaic is a working original title. The game uses native Views, central theme tokens, and safe-area insets. Smaller screens can scroll; text follows system font scaling. No backend or HTTP API is involved.

Run `npm start`, then open on Android with Expo Go or the project's compatible development build.

Select a tray piece, then tap the board cell corresponding to its bounding box's top-left corner. Invalid placements keep the selection available. Successful placements clear selection and update scores; engine revision checks reject repeated taps. Completing the tray deals three more pieces. Restart confirms before resetting an in-progress game. Game over offers immediate replay.

Best score currently lasts for this app session only. Persistent storage remains a later milestone. Drag-and-drop and placement previews are now implemented. Clear/combo effects are described below. This screen already supports the select-piece/select-cell control path as an alternative to future dragging.

Verification: `npm run typecheck` and `npm test`. Controller tests cover success, rejected placement, duplicate taps, and restart. Native screen rendering, system-bar behavior, font scaling, screen-reader navigation, and dialog interaction require Android device/emulator checks; they are not covered by the Node test suite.

## Clear and combo feedback

Accepted placements now produce a short original click. Clearing lines overlays a colorful flash and particles; consecutive clears show a combo banner and a rising-pitch chime. System reduced-motion mode uses static feedback without moving particles. Sound defaults on, vibration defaults off; both have switches and last for the current app session. No microphone or background-playback permissions are requested.

Sounds are bundled PCM WAV files generated by `python3 scripts/generate-sounds.py`, using only original synthesized tones. They play offline. Platform audio/haptic failures are optional and never change engine state. Verify loudness, device silent-mode behavior, rapid placements, vibration support, and reduced motion on Android. Both drag-and-drop and tap-to-place are available.


## Milestone 3: drag-and-drop

Use a mouse on web or one finger on Android to drag a tray piece. The floating piece uses full board-cell size and sits above the pointer. Its top-left corner determines the target. Mint outlined cells indicate a valid candidate; pink outlines indicate an invalid candidate. Out-of-bounds coordinates remain invalid rather than being clamped. Invalid releases return toward the tray, respecting reduced motion. Tap-to-place remains available.

Movement uses Reanimated shared values. Gesture callbacks run on JS for portable interaction coordination; React preview state changes only when the candidate grid coordinate changes. Profile on Android before moving more gesture computation to worklets. The board is measured in window coordinates and remeasured on scroll/layout and pickup. Dragging disables scrolling; restart, backgrounding, and game revisions invalidate pending moves.

Coordinate mapping has unit tests. Web and Android bundle checks cannot establish real pointer behavior: manually verify fast drags, cancellation, touch scrolling, board edges, invalid overlap, reduced motion, background/resume, and orientation/resize on actual targets.
